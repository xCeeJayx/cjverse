# Phase 1 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the complete Phase 1 MVP for CJVerse: a unified TypeScript monorepo featuring core combat and identity formulas, Supabase/Drizzle database layer, generative asset pipeline with procedural fallback, Discord bot with `/hunt`, `/inventory`, and `/duel`, an authoritative real-time WebSocket skirmish server, and Next.js duel arena web client.

**Architecture:** Monorepo with Turborepo and pnpm workspaces comprising three shared packages (`packages/game-logic`, `packages/db`, `packages/asset-pipeline`) and three applications (`apps/bot`, `apps/game-server`, `apps/web`). The game server runs a deterministic 3v3 turn machine over WebSockets, the Discord bot drives player card collection and challenge creation, and the web client renders the live duel arena over HTML5 Canvas.

**Tech Stack:** TypeScript (Strict Mode), Node.js v20+, Turborepo, pnpm, Vitest, Drizzle ORM + PostgreSQL / Supabase, Discord.js v14, `@napi-rs/canvas`, `ws` WebSocket server, Next.js 14+ (App Router), Tailwind CSS.

**Spec:** [PROJECT_SPEC.md](file:///c:/Users/IDEAPAD/cjverse/PROJECT_SPEC.md)

## Global Constraints

- **Language & Runtime:** TypeScript (Strict Mode), Node.js v20+.
- **Monorepo Engine:** Turborepo with `pnpm` workspaces.
- **Testing Framework:** Vitest across all packages and apps.
- **Database & Auth:** PostgreSQL (Supabase) + Drizzle ORM; Discord Snowflake string IDs for users.
- **Discord Bot:** `discord.js` v14, `@napi-rs/canvas` for dynamic image buffers.
- **Web Frontend:** Next.js 14+ (App Router), Tailwind CSS, HTML5 Canvas API.
- **Game Server:** Node.js WebSocket server (`ws`) with deterministic state machine.
- **Combat Format:** 3v3 Lineup (Slot 1: Vanguard, Slot 2: Striker, Slot 3: Conduit).
- **Turn Timer:** 15-second action phase with automated fallback logic.
- **Damage Floor:** $\max(1, \lfloor\text{Raw Damage} \times \text{Mitigation}\rfloor)$.
- **Mitigation:** $\frac{1000}{1000 + \text{Target DEF}}$.

## Review Focus

1. **Damage Floor on Extreme Defense:** Attacker with minimal ATK against defender with arbitrarily large DEF must inflict at least 1 damage, never 0, negative, or NaN (Pinned to Task 6).
2. **Duplicate Card in Active Lineup:** Lineup assignment must reject placing the same card UUID into multiple roles (e.g. both Vanguard and Striker) (Pinned to Task 8).
3. **Incomplete Lineup Duel Challenge:** `/duel` must reject challenges if either challenger or target has fewer than 3 assigned cards in `activeLineup` (Pinned to Task 13).
4. **Turn Timeout Fallback Execution:** When the 15-second action timer hits 0 with no client action, server must auto-execute fallback action against lowest HP enemy and advance turn (Pinned to Task 16).
5. **Missing Asset Slices Graceful Fallback:** When image slices are absent from disk, `renderCardComposite` must produce a valid procedural card without throwing (Pinned to Task 10).
